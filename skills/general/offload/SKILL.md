# 일반 작업 위임

원칙: 원문(문서·웹 페이지·대량 파일)은 Claude 대화에 넣지 않는다. agy가 읽고 결과 파일을 만들며, Claude는 요약 몇 줄과 필요한 부분만 읽는다.

## 0. 시작 전 확인

1. `command -v agy`. 없으면 이 스킬을 쓰지 않고 Claude가 직접 처리한다(사용자에게 한 줄로 알림).
2. 맡기지 않고 직접 하는 일:
   - 읽을 양이 적은 일(파일 1~2개, 짧은 질문) — 위임 비용이 더 큼
   - 시스템 변경(디스크 포맷·삭제·설치·설정 변경), 로그인·결제가 필요한 일, 비밀번호·키를 다루는 일
   - 결과를 바로 실행해야 하는 파일 작업 — 정리안만 맡기고 실행은 5단계에서 직접
3. 개인정보 확인: agy로 보내는 내용은 외부(Google)로 전송된다. 대상에 개인 문서, 신분증·계약서·의료·금융 자료, 이름·연락처 목록이 있으면 실행 전에 사용자에게 확인한다. 확인 없이 보내지 않는다.

## 1. 모델 선택

| 작업 | 모델 |
|---|---|
| 요약·번역·단순 조사 | `gemini-3.8-flash-medium` (기본) |
| 여러 자료 비교, 긴 문서, 정리안 | `gemini-3.8-flash-high` |
| 판단이 어려운 분석, 글 품질이 중요한 초안 | `gemini-4-argon-medium` |
| 꼼꼼한 넓은 조사 (사용자가 '꼼꼼하게·자세히·빠짐없이' 요청, 독립 주제 3개 이상) | `gemini-pro-orchestrator-neon` — 하위 에이전트로 나눠 조사. 시간·한도 약 1.5~2배, 결과가 더 상세하고 미확인 항목을 표시함. 3단계 대기는 5분 이상 걸릴 수 있음 |

사용자가 `--model`을 주면 따른다. 한도 확인과 소진 시 대체 순서는 delegate 스킬 2단계를 따른다. 모두 소진되면 사용자에게 대기 또는 Claude 직접 처리를 묻는다.

## 2. 지시 파일

scratchpad에 `offload_<주제>_instr.txt`로 **작업만** 적는다. 읽기 전용 규칙과 출력 형식은 스크립트가 붙인다.
- 대상: 파일·폴더 경로, 또는 조사 주제와 범위(기간·지역·가격대)
- 원하는 결과 형태: 표 열 이름, 비교 기준, 분량, 결과 언어
- 판단 기준이 있으면 명시(예: "공식 자료 우선, 2026년 이후 정보만")

## 3. 실행

```sh
S=<scratchpad>; OFFLOAD_DIRS=<함께 읽을 폴더(':' 구분, 선택)> \
  ~/.claude/skills/offload/run-offload.sh <작업 폴더> $S/offload_<주제>_instr.txt <결과 파일> [모델]
```

- 작업 폴더: 대상 파일이 있는 폴더. 웹 조사만 하면 scratchpad.
- 결과 파일: 사용자가 보관할 결과는 `~/agent/notes/<YYYYMMDD>-<주제>.md`, 일회성은 scratchpad. 같은 이름이 있으면 거부되므로 새 이름을 쓴다.
- agy는 plan 모드(읽기 전용)로 실행되어 파일을 만들거나 고치지 못한다. 결과 파일은 스크립트가 출력에서 잘라 저장한다.
- 오래 걸릴 수 있으므로 Bash `run_in_background: true`로 실행하고 완료 알림을 기다린다(웹 조사 1건 약 30초).
- 출력의 요약 몇 줄과 마지막 줄 `OFFLOAD_RESULT {...}`만 읽는다. JSON에 `new_models`가 있으면 사용자에게 한 줄로 알리고 평가 여부를 묻는다(모델은 자동으로 바꾸지 않음, 절차는 delegate 스킬 "새 모델 평가 절차"). `ok: false`면 `agy` 항목(AGY_DENIED·AGY_USAGE)으로 원인을 보고 지시를 고쳐 1회 재실행한다.

## 4. 결과 검토

- 결과 파일 전체를 읽지 않는다. 사용자 질문에 답하는 데 필요한 부분만 `grep`·`sed -n`으로 본다.
- 확인할 것: 요청한 범위를 다 다뤘는지, 출처가 있는지, 추정이 사실처럼 적히지 않았는지. 핵심 수치·결론 1~2개는 출처를 직접 확인한다(웹이면 WebFetch).
- 빠졌거나 틀렸으면 지시를 구체화해 1회 재위임한다. 그래도 부족하면 그 부분만 Claude가 직접 처리한다.

## 5. 정리안 실행 (파일 이동·이름 변경 등)

agy 결과에 명령(sh 블록)이 있으면:
1. Claude가 명령을 검토한다(대상 경로, 덮어쓰기·삭제 여부).
2. 사용자에게 바뀌는 내용 요약(건수, 예시 몇 개)을 보여 주고 승인을 받는다.
3. 삭제는 하지 않고 휴지통(`~/.Trash`) 또는 `~/agent/storage/` 아래로 옮긴다.
4. Claude가 실행하고 결과 건수를 확인한다.

## 6. 보고

결과 파일 경로, 핵심 내용 3~5줄, 사용한 agy 모델, 확인하지 못한 것을 짧게 알린다.
