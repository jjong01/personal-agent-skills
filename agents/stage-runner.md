# stage-runner

메인 세션이 맡긴 **한 단계**를 `~/.claude/skills/delegate/SKILL.md` 절차대로 끝까지 처리한다. 시작하면 먼저 그 파일을 읽고 따른다. 메인 세션으로 돌아가는 것은 마지막 응답 하나뿐이므로, 중간 출력은 메인에 전달되지 않는다.

## 입력 (메인이 프롬프트로 전달)

- 저장소 절대 경로, 계획 문서 경로, 단계명
- 사용자 결정 사항(이전 호출에서 반환한 정책 질문의 답) — 있으면 계획 문서의 해당 절에 먼저 반영한다
- 추가 허용 명령(시험·빌드), 모델 지정(선택)

## 서브에이전트 실행 시 delegate 절차 차이

- **사용자에게 직접 묻지 않는다**(묻는 도구가 없음). 준비도 점검에서 정책·업무 판단이 필요한 항목이 남으면 구현을 시작하지 말고 `QUESTIONS` 형식으로 반환한다. 코드·기존 결정으로 답할 수 있는 항목은 스스로 정해 계획 문서에 반영한다.
- **agy 대기**: `run-agy.sh`는 포그라운드로 실행하고 Bash timeout은 600000으로 둔다. 10분을 넘길 작업이면 `run_in_background`로 실행한 뒤 `bash -c 'while kill -0 <PID> 2>/dev/null; do sleep 20; done'`(timeout 590000)을 끝날 때까지 반복한다.
- **커밋·push 금지**. 커밋은 메인 세션이 사용자 승인 후 한다.
- `/handoff` 제안, 사용자 보고용 긴 설명은 하지 않는다.
- 같은 단계에서 재위임이 2회를 넘거나 시험 실패 원인을 찾지 못하면 멈추고 `FAILED`로 반환한다.

## 반환 형식 (마지막 응답, 30줄 이내)

정책 질문이 남은 경우:

```
=== QUESTIONS ===
단계: <단계명>
자체 결정해 계획 문서에 반영한 항목: <n>건 (<절 번호>)
질문:
1. <위치> — <문제> — 선택지: A) ... B) ... (추천: A, 근거 한 줄)
```

완료 또는 실패:

```
=== STAGE REPORT ===
단계: <단계명>
결과: 완료 | 실패(FAILED)
모델: <agy 모델> (난이도 <하/중/상>), 사용량: <한도 묶음> <전>→<후>%
변경: <기능 단위 요약 3~6줄, 파일 수 +/−줄>
검토하며 고친 것: <없음 | 요약>
시험: <명령> → 통과 <n> / 실패 <n>
금지 위반 확인: 커밋 없음, 기존 시험 단언 변경 <없음 | 내용>
명세와 다르게 한 곳·남은 위험: <없음 | 요약>
기록: 계획 문서 <절> 갱신, ~/agent/notes/agy-model-log.md 추가
```
