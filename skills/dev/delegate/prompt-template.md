# agy 지시문 템플릿

`<...>`를 채우고 해당 없는 줄은 지운다.

```text
저장소 <절대 경로> (<스택 한 줄>)에서 작업해 줘. 저장소의 AGENTS.md 규칙을 따라.

[명세]
<문서 경로>를 읽고 <절 번호>를 그대로 따라. 이번 범위는 <단계명>뿐이야. 범위 밖은 고치지 마.

[해야 할 일]
1. <파일 또는 영역>: <변경 내용>
2. ...

[시험]
- <추가·수정할 시험>
- 완료 조건: `<시험 명령>`이 통과할 것. 실패하면 원인을 고쳐 다시 실행해. 최대 5회.
- 시험 명령은 적힌 그대로 실행해. 앞에 환경 변수(JAVA_HOME= 등)나 cd를 붙이지 마. 실행이 안 되면 고치지 말고 보고에 적어.
- 컴파일 확인이 필요하면 `<허용된 컴파일 명령>`만 써(옵션 순서·하위 목표를 바꾸면 권한 거부로 중단됨).

[금지]
- git commit·push·reset·checkout, 브랜치 변경 금지
- DB 접속·마이그레이션 실행, .env 읽기 금지
- 기존 시험의 단언(기대값)을 바꿔서 통과시키지 마. 바꿔야 한다면 바꾸지 말고 보고에 이유를 적어.
- 명세와 다르게 판단해야 할 곳은 임의로 정하지 말고 명세대로 하되 보고에 적어.
- 시험 편의를 위해 private 멤버를 공개하거나 운영 코드를 바꾸지 마.

[보고]
작업이 끝나면 마지막에 아래 형식만 출력해. 코드·로그 전문은 넣지 마.

=== REPORT ===
결과: 완료 | 일부 완료 | 실패
변경 파일: <경로> — <한 줄 요약> (파일마다 한 줄)
시험: <명령> → <통과 n / 실패 n>
명세와 다르게 한 곳: <없음 | 위치와 이유>
불확실한 곳: <없음 | 위치와 이유>
```

## 준비도 점검용 (`AGY_MODE=plan`)

```text
너는 이 계획을 구현할 개발자다. 코드는 수정하지 마.
저장소 <절대 경로>의 <문서 경로>를 읽고(범위: <절 번호 또는 단계명>), 필요하면 언급된 코드 위치만 확인해.
구현을 시작하기 전에 답이 필요한 모호한 점·누락된 정보·명세와 코드가 어긋나는 곳만 최대 10개 나열해.
중요한 것부터, 각 항목은 한 줄로: '위치(절 번호/파일:줄) — 문제 — 필요한 결정'.
문제가 없으면 '준비 완료'라고만 써.
```

## 브라우저 확인용

Orca 세션에서는 이 지시문 파일을 `orchestration` 스킬의 `worker-start --agent antigravity --spec-file <경로>`로 넘기고, Orca 밖에서는 `AGY_BROWSER=1 run-agy.sh`에 넘김.

```text
저장소 <절대 경로>, 대상 URL <URL>에서 아래 브라우저 전용 항목을 확인함. 앱 코드는 수정하지 않음(브라우저 확인 스크립트만 프로젝트 CLAUDE.md 지정 경로에 작성·실행함).

[서버]
- 포트 <포트 번호> 실행 여부를 먼저 확인하고, 실행 중이면 재사용함.
- 재시작은 백엔드 코드·.env·의존성·번들러/프록시 설정이 바뀐 경우에만 수행함.
- 본인이 직접 띄우고 PID를 기록한 프로세스만 종료·재시작함(명령·포트가 같다는 이유로 소유 간주 금지). 사용자 실행 또는 소유 불명 서버는 끄지 말고 보고에 재시작 필요를 적어 사용자에게 요청함.
- <해당 시: 포트당 서버 담당 지정 여부 / 마지막 확인 작업자 종료까지 서버 유지 조건>
- DB 마이그레이션·SQL 직접 실행 금지.

[확인 방식]
- 데이터 준비와 상태 검증은 API로 먼저 처리하고, 브라우저는 렌더링(레이아웃·높이 튐·로딩/빈 상태·모달 위치 등)만 확인함.
- 아래 체크리스트 항목을 Playwright 스크립트 하나로 묶어 일괄 실행하고 로그만 판독함(클릭마다 모델 턴 소모 금지). 스크립트 위치: <프로젝트 CLAUDE.md 지정 경로>.
- 셀렉터를 모르는 첫 화면만 agy 브라우저 도구(chrome-devtools MCP)나 Orca 브라우저로 탐색하고, 이후 스크립트로 고정함.
- 로그인: <프로젝트 문서의 로컬 시험 계정(.env·DB 탐색 금지)>. storageState로 로그인을 재사용하며 상태 파일은 저장소 밖(<시스템 임시 폴더 또는 ~/.cache 하위 경로>)에 두고 커밋 금지.
- 높이·문구·배치 등은 DOM 측정값으로 판정하고, 스크린샷은 실패 항목만 <저장소 밖 임시 경로>에 저장함.
- 같은 화면·같은 계정으로 병렬 실행하지 않음.

[시험 데이터]
- 로컬 환경에서 앱·API 경유로만 생성함(DB 클라이언트 직접 실행 금지). 이름에 구분 접두어 `<접두어>` 사용.
- 기본은 확인 완료 후 생성 데이터를 모두 삭제함.
- 실패 항목 재확인에 필요한 데이터만 예외로 보존 가능하며, 보존 시 보고에 접두어와 식별자(ID)를 기록함(사용자 보존 지시 시 유지).

[확인 항목]
1. <화면 위치/시나리오> — <동작> — 기대(DOM 측정 기준): <결과>
2. ...

[보고]
작업이 끝나면 아래 형식만 출력함.

=== REPORT ===
서버: 재시작 여부(<예|아니오|사용자 요청 필요>), 포트(<번호>), 남은 PID(<PID|없음>), 띄운 주체(<본인|기존 사용자|소유 불명>)
스크립트: <경로>
시험 데이터: <전부 삭제 | 보존 — 접두어·ID 목록 및 사유>
결과:
1. 통과 | 실패 — <DOM 측정값 등 한 줄 근거> <실패 시: (스크린샷: 경로)>
2. ...
```
