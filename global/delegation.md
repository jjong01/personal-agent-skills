# 위임 세부 규칙

Claude Code 전용 위임 세부 규칙, AGENTS.md에서 import

## A. 서버 실행·재실행 (브라우저 확인 작업자 담당)

- 구현 작업자는 앱 서버를 띄우지 않음. 단위·API 시험만 수행하며, 시험 중 서버를 띄웠으면 종료함.
- 브라우저 확인 작업자는 포트로 서버 실행 여부를 먼저 확인하고, 실행 중이면 재사용함.
- 재시작은 백엔드 코드·`.env`·의존성·번들러/프록시 설정이 변경된 경우에만 수행함.
- 본인이 직접 띄우고 PID를 기록한 프로세스만 종료·재시작함. 명령이나 포트가 같다는 이유로 본인 소유로 간주하지 않음.
- 사용자가 띄운 서버나 소유 불명 서버는 종료하지 않고, 사용자에게 재시작을 요청함.
- 같은 화면을 수정하는 구현 작업자의 `worker_done`(또는 `STAGE REPORT`) 전에는 브라우저 확인을 시작하지 않음.
- 확인 작업자가 여럿이면 포트당 서버 담당을 1명으로 지정하고, 마지막 확인 작업자가 끝날 때까지 서버를 유지함.
- DB 마이그레이션 및 SQL 실행은 사용자가 직접 수행함.
- 완료 보고에 재시작 여부, 포트, 남은 PID, 서버를 띄운 주체(본인·기존 사용자·소유 불명 등)를 반드시 기록함.

## B. 브라우저 확인 방식

- 실행 기준: 화면 변경이 있는 계획은 마지막 구현 단계 커밋 후 구현 작업자와 별도의 agy 작업자로 브라우저 확인을 1회 기본 실행함. 화면 변경이 없는 계획은 생략함.
- 확인 범위: 브라우저로만 확인 가능한 항목(레이아웃·높이 튐·로딩/빈 상태·모달 위치 등)으로 한정함. 로직·데이터 검증은 API·단위 시험으로 처리함.
- 수동 확인 및 메인 제한: 위 범위 외 항목은 사용자에게 수동 확인 표(화면 위치·동작·기대 결과, 계획 단계·체크리스트 기준)를 제공하고 체크리스트에 기록함. Claude 메인 세션은 브라우저 도구로 확인하지 않음.
- 일괄 실행: 체크리스트 항목을 Playwright 스크립트 하나로 묶어 일괄 실행하고, 작업자는 실행 로그만 판독함. 클릭마다 모델 턴을 쓰지 않음.
- API 우선: 데이터 준비와 상태 검증은 API로 먼저 처리하고, 브라우저는 렌더링만 확인함.
- 로그인 재사용: `storageState`로 로그인 세션을 재사용함. 상태 파일은 저장소 밖(예: 시스템 임시 폴더 또는 `~/.cache` 하위)에 두고 커밋하지 않음.
- 판정·증거: 높이·문구·배치 등은 DOM 측정값으로 판정하며, 스크린샷은 실패 항목만 저장함.
- 초기 탐색: 셀렉터를 모르는 첫 화면만 agy 브라우저 도구(chrome-devtools MCP)나 Orca 브라우저로 탐색하고, 이후 같은 화면은 스크립트로 고정함.
- 병렬 제한: 같은 화면·같은 계정으로 브라우저 확인을 병렬 실행하지 않음.
- 스크립트 위치: 프로젝트별로 정해 프로젝트 `CLAUDE.md`에 기록함(공통 규칙에는 원칙만 둠).
- 시험 계정: 프로젝트 문서(`AGENTS.md`·`CLAUDE.md`)에 정해진 로컬 계정을 사용함. `.env`·DB 탐색 금지. 계정이 없거나 로그인에 실패하면 중단하고 사용자에게 요청함.
- 재확인: 실패 항목만 다시 확인함.

## C. 시험 데이터

- 로컬 환경에서 앱 또는 API 경유로만 생성함. DB 클라이언트 직접 실행 금지.
- 생성 데이터 이름에 구분 접두어를 사용해 기존 데이터와 구별함.
- 기본은 확인 완료 후 생성한 데이터를 모두 삭제함.
- 보존 예외: 실패 항목 재확인에 필요한 데이터만 보존 가능함. 보존 시 보고에 접두어와 식별자(ID)를 기록하고, 재확인 통과 후 삭제함. 사용자가 보존을 지시한 경우에도 유지함.

## D. 기타 위임 운영 세부

### 실행 경로·보고 처리
- Orca 세션(`ORCA_TERMINAL_HANDLE`·`ORCA_CLI_COMMAND` 설정 또는 Orca chat): 구현·`/delegate`·`/offload`·브라우저 확인·의견 요청 모두 `orchestration` 스킬의 `worker-start`(`--agent antigravity` / `grok`)로 실행함. 의견 요청은 `antigravity`·`grok` 읽기 전용 작업자를 병렬로 시작해 `worker_done` 보고를 종합함. 코디네이터(Claude 메인)가 diff 검토, 시험 실행, 체크리스트 갱신, agy 사용량 기록을 맡음.
- Orca 밖: 구현·`/delegate`·브라우저 확인은 `stage-runner`(agy), 의견 요청은 `agy -p`·`grok -p`를 직접 실행함.
- `QUESTIONS` 수신 시 사용자에게 묻고 답을 붙여 재실행함. `STAGE REPORT`(또는 `worker_done`) 수신 시 요약 후 커밋 승인을 받음.

### 커밋 전 계획 문서 동기화
- 현재 작업의 계획 문서가 있으면 매 커밋 전 구현 항목의 완료 체크(`[x]`)와 일시를 확인·갱신해 커밋에 포함함.
- 메인 세션의 소규모 수정, 화면 확인 후 수정, 계획 외 변경(항목 추가)도 동일하게 반영함.

### 백그라운드 서브에이전트·병렬 요청·병합 전 리뷰
- 백그라운드 서브에이전트(`sonnet`, 필요 맥락 전달): 문서·계획·리뷰·스크립트·설정·agy 대기 등 비제품 다단계 작업, 또는 모든 agy 한도 소진 시 코드 작업에 사용해 메인 대화를 유지함.
- 1~2개 명령 작업, 파괴적 확인(포맷·삭제), 커밋·push는 메인에 둠. 서브에이전트는 커밋·push를 금지하고 정책 질문은 반환하며, 메인은 서브에이전트가 작업 중인 파일을 동시에 수정하지 않음.
- 병렬 요청: 대상 파일·영역이 겹치지 않을 때만 최대 3개 동시 실행함. 코드 작업은 빌드·시험 충돌 방지를 위해 `isolation: worktree`를 사용함. 같은 파일·공유 컴포넌트를 건드리는 작업과 1~3줄 수정은 한 에이전트에서 순차 처리함.
- 병합 전 리뷰: 피처 브랜치를 통합 브랜치(예: `develop`)에 병합하기 직전 `/code-review low`를 백그라운드 서브에이전트로 자동 실행해 요약만 읽음. 변경 경로·diff에 인증·로그인·세션·권한·역할·결제·토큰·비밀번호·개인정보·파일 업로드가 포함되면 `/security-review`를 병행함. 이와 함께 Grok 읽기 전용 교차 리뷰를 시범 수행하고(첫 실행 후 채택 여부 결정) 결과를 보고해 수정 여부를 사용자가 결정하게 함. `/simplify`는 제안 시에만 실행함.

### 모델·할당량 안내
- agy 위임 작업: Claude 모델을 추천하지 않음. 착수 전 `~/.cache/agy-quota.tsv`에서 Gemini 5시간/주간 잔여량을 한 줄로 안내하고, 보고 요약 시 사용된 agy 모델과 할당량 변화를 전달함.
- Claude 단독 작업: 권장 모델(`opus`·`sonnet`·`haiku`)을 명시함. 현재 모델과 같으면 바로 진행하고, 다르면 전환을 대기함. 긴 세션에서는 모델 전환 시 프롬프트 캐시가 재구축되므로 `/clear` 선행을 제안함.

### 세션 리셋 (`/clear`·`/handoff`)
- 내장 명령을 직접 실행하지 않고, 명확히 도움 될 때 보고 마지막 줄에 권장함.
- 판단 기준: (1) 자연스러운 경계인가(작업 완료 또는 자리 비움), (2) 지금 대화가 끝나면 유실될 내용이 있는가.
- 권장 검토 시 확인 항목: `git status` 및 미푸시 커밋, 계획 문서·체크리스트에 현재 단계와 결정 기록 여부, 실행 중인 서브에이전트·agy 없음, 미결 질문 없음.
- 대화에만 있던 상시 지시(커밋 금지 파일, 환경·DB 주의사항 등)는 `/clear` 권장 전 프로젝트 `CLAUDE.md`나 메모리로 옮김.
- 유실 없음 → `` `/clear` 권장 — 다음 시작 문장: <계획 문서 경로 · 다음 단계 · 마지막 커밋 · 브랜치> ``(미푸시 시 `push 안 됨` 표기). 미기록 내용 있음 → 먼저 기록하거나 `/handoff` 사용함.
- 경계당 최대 1회만 권장하고, 사용자가 거절하면 다음 경계까지 반복하지 않음. 맥락 크기만으로는 권장하지 않음(자동 요약 처리). 다른 날 이어하거나 다른 PC로 이동할 때 `/handoff`를 사용함.
