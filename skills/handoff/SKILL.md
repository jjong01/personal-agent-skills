# 인계 메모

맥락을 `/compact`로 요약해 계속 들고 가는 대신, 다음 대화에 꼭 필요한 내용만 파일로 남기고 `/clear`로 맥락을 비운다.

- 저장 위치: `~/agent/notes/handoff/`
- 파일명: `YYYYMMDD-HHMM-<작업폴더명>-<주제>.md` (주제는 2~4단어, 공백은 `-`)

## 저장 (`/handoff` 또는 `/handoff <메모할 내용>`)

1. 현재 상태를 확인한다: 작업 폴더(`pwd`), git이면 브랜치·`git status --short`·마지막 커밋, SVN이면 `svn status`.
2. 아래 형식으로 파일을 쓴다. 대화 전체를 옮기지 말고 **다음 대화가 처음부터 다시 조사하지 않아도 되는 정보**만 남긴다. 전체 200줄 이내.

```markdown
# 인계: <주제>
- 작성: YYYY-MM-DD HH:MM
- 작업 폴더: <절대 경로>
- 저장소 상태: <브랜치, 커밋 안 된 변경 요약 / 해당 없음>

## 목표
<무엇을 왜 하는지 1~3줄>

## 완료한 것
- <결과 위주. 변경한 파일은 경로와 핵심 변경만>

## 결정 사항
- <정한 것과 이유. 사용자가 고른 선택지 포함>

## 남은 할 일
1. <다음에 바로 할 일부터 순서대로>

## 주의할 점
- <막혔던 문제와 원인, 건드리면 안 되는 것, 미확인 사항>

## 참고
- <다시 읽어야 할 파일·문서·명령. 긴 로그·코드는 붙이지 말고 위치만 적음>
```

3. 비밀번호·토큰·API 키 값은 적지 않는다(위치만 적는다).
4. 저장한 경로를 알려 주고, 다음 순서를 안내한다: `/clear` → 새 대화에서 `/handoff load`.

## 불러오기 (`/handoff load` 또는 `/handoff load <파일>`)

1. 파일을 지정하지 않으면 `~/agent/notes/handoff/`에서 **작업 폴더가 현재 폴더와 같은 가장 최근 파일**을 고른다. 없으면 최근 파일 5개를 보여 주고 고르게 한다.
2. 파일을 읽고, 메모의 작업 폴더가 현재 폴더와 다르면 알린다.
3. 저장소 상태를 다시 확인해 메모 이후 바뀐 점(새 커밋, 다른 브랜치, 변경 파일)이 있으면 알린다.
4. 목표와 "남은 할 일" 1번을 한두 줄로 요약하고 바로 이어서 진행할지 묻는다. 메모에 적힌 파일 외에는 필요할 때만 읽는다.
