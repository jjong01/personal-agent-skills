# 이미지 편집

원칙: **이미지를 Claude 대화에 넣지 않는다.** 원본·사용자 제공 이미지는 열어 보지 않고 크기·형식 정보만 확인한다. 눈으로 확인할 때는 500px 이하 미리보기 1장만 본다(이미지는 이후 모든 응답에서 다시 읽힘). 사용자가 이미지를 붙여 넣으려 하면 파일 경로로 달라고 안내한다.

도구: ImageMagick가 없을 수 있으므로 `sips`(macOS)와 Python PIL을 쓴다.

## 1. 분류

| 종류 | 예 | 처리 |
|---|---|---|
| 파일 작업 | 교체, 자르기, 크기 조정, 형식 변환, 이름 정리, 여러 장 정리 | 2단계 없이 4단계에서 `sips`·PIL로 직접 처리 |
| 내용 편집·생성 | 글자 수정, 이름·얼굴 가리기, 색·밝기 보정, 새 이미지 | 2 → 3 → 4단계 |
| 판단 | AI 생성 사진인지, 결과가 맞는지 | 미리보기 1장으로 판단, 확신 없으면 그렇다고 답함 |

크기·형식 확인: `sips -g pixelWidth -g pixelHeight -g format <파일>`. PDF에서 이미지 추출은 PIL로 하지 못하므로 macOS `sips -s format png <pdf> --out <png>`(첫 쪽)로 변환한다.

## 2. 개인정보 확인 (내용 편집만)

agy로 보내면 이미지가 외부(Google)로 전송된다. 경로·파일명·요청에 환자·회원·직원 사진, 엑스레이, 이름·연락처가 보이는 문서가 있으면 실행 전에 사용자에게 확인한다.
- 이름·얼굴 가리기처럼 위치가 정해진 작업은 외부 전송 없이 PIL로 직접 처리할 수 있는지 먼저 검토한다(사각형 채우기·흐림).
- 확인 없이 외부로 보내지 않는다.

## 3. agy 편집 실행 (내용 편집만)

지시 파일에 **바꿀 것만** 짧게 적는다(예: `글자 '삼대치과'를 '365삼대치과'로 바꿈`). 유지 조건과 도구 사용 규칙은 스크립트가 붙인다.

```sh
S=<scratchpad>; ~/.claude/skills/image-edit/run-image.sh <원본> $S/instr.txt $S/<이름>_edited.<원본 확장자> [모델] [--keep-size]
```

- 결과는 scratchpad에 만든다(프로젝트 파일은 4단계에서 교체). 원본과 같은 경로는 거부된다.
- 기본 모델 `gemini-3.8-flash-medium`. 글자가 많거나 1차 결과가 어긋나면 `gemini-4-argon-medium`. 한도 확인·소진 시 대체 순서는 delegate 스킬 2단계를 따른다. 실행 출력에 `AGY_NEW_MODELS`가 나오면 사용자에게 한 줄로 알리고 평가 여부를 묻는다(자동 전환 없음, delegate 스킬 "새 모델 평가 절차").
- 스크립트가 agy 결과(JPEG, 크기 임의)를 찾아 원본 비율로 가운데를 잘라 원본 크기·확장자 형식으로 저장한다. 새 이미지처럼 크기를 유지해야 하면 `--keep-size`.
- 마지막 줄 `IMAGE_RESULT {...}`만 읽는다(`out`, `size`, `preview`). `ok: false`면 지시를 구체화해 1회 재시도하고, 또 실패하면 사용자에게 보고한다.
- 소요 약 1~2분. Bash `run_in_background: true`로 실행하고 완료 알림을 기다린다.

## 4. 확인과 적용

1. `preview`(500px) 1장을 열어 지시대로 바뀌었는지, 다른 부분이 망가지지 않았는지 확인한다. 글자 오타·깨짐이 있으면 3단계 재시도.
2. 사용자에게 미리보기 경로와 함께 결과를 알리고 교체 승인을 받는다(파일 작업만 한 경우는 생략 가능).
3. 원본 백업: `~/agent/storage/image-backup/<프로젝트>/<YYYYMMDD>/<원본 상대경로>`에 복사.
4. 교체: 같은 파일명으로 덮어쓴다(참조 경로가 바뀌지 않게). 파일명을 바꿔야 하면 `grep -rn '<옛 이름>'`으로 참조를 찾아 함께 고친다.
5. 프로젝트 지시 파일에 정적 파일 버전 갱신 절차가 있으면 실행한다(예: samdae `frontend/scripts/asset-versions.mjs`는 `npm run dev`·`build` 전에 자동 실행).
6. 빌드 결과물 폴더(`dist/` 등)는 직접 고치지 않는다.

## 5. 보고
